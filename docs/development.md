# 開発・検証ガイド

対応環境と普段使いの配置手順は[README](../README.md)を参照してください。以降のコマンドはリポジトリのルートで実行します。

## ビルド・自動テスト

```sh
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
xcodebuild -project AutoMute.xcodeproj -scheme AutoMute \
  -configuration Debug -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath build build test
```

テストはアプリを起動しないXCTestです。Core Audio操作を代替実装に差し替えるため、実機の出力先・音量・ミュートを変更しません。設定保持のテストも専用の一時ドメインを使い、普段使いの設定を変更しません。

Release版は上のコマンドの`Debug`を`Release`にし、末尾を`build`だけにして作成できます。

## 起動・終了とログ確認

配置済みのAutoMuteが動いている場合は、メニューから終了してから開発用の版を起動します。

```sh
open ./build/Build/Products/Debug/AutoMute.app
```

別のターミナルでログを表示します。

```sh
log stream --level debug --style compact --predicate 'subsystem == "local.AutoMute"'
```

ONで起動すると現在の出力が記録され、監視を開始します。ログで変更前後のID・名前・種類・Transport Type・端子種別、ミュートの設定要求と反映確認を確認できます。UIDはログに出力しません。ON/OFFの操作はnoticeレベル、変更通知の受信と重複通知はdebugレベルで記録します。

ログには機器名が含まれます。共有する場合は個人情報を取り除いてください。

メニューの終了操作のほか、Xcodeの停止操作やActivity Monitorからも終了できます。実行ファイルをターミナルから直接起動した場合はCtrl+Cでも終了します。SIGINT・SIGTERMによる終了ではリスナーを解除します。強制終了時の終了ログは保証しません。

## 一度限りのミュート検証

この手順は**実際の内蔵スピーカーをミュートします**。メニューから常駐アプリを終了し、macOSの出力先に内蔵スピーカーを選んで実行します。この起動ではメニューバーを表示せず、保存済みのON/OFFにかかわらず検証を一度だけ行います。

```sh
./build/Build/Products/Debug/AutoMute.app/Contents/MacOS/AutoMute --verify-mute-once
```

- 内蔵スピーカーを識別でき、Main要素のミュートが書き込み可能な場合だけONにします。
- 設定前に変更リスナーを登録し、通知と読み戻しで結果を確認します。通知がない場合も1秒後に一度読み戻します。再書き込みや音量0への変更は行いません。
- 成功またはミュート済みの場合は終了コード0、失敗は1で終了します。詳細はLoggerのログに出力します。
- ミュート解除は行いません。検証後に必要ならmacOS側で解除してください。
- この引数はDebug専用です。Releaseではエラーを記録して終了し、設定を書き換えません。

Xcodeでは、Product → Scheme → Edit Scheme → Run → Argumentsに`--verify-mute-once`を追加して実行できます。テストにはこの引数を引き継がない設定です。

音量維持を確認する場合は、再生を止めてmacOS側で内蔵スピーカーの音量を設定し、ミュート実行後も設定値が変わっていないことを確認します。ログの設定要求から確認までの時間は、物理的な切断や実際の出力切り替えからの時間ではありません。

## 実機での確認

まず再生を止めた状態で確認します。

1. 内蔵スピーカーを選び、ミュートOFFにして起動する。起動やONへの変更だけではミュートされないことを確認する。
2. Bluetoothイヤホンを接続して出力先に選ぶ。内蔵からBluetoothへの変更ではミュート操作が記録されないことを確認する。
3. イヤホンを切断する。内蔵スピーカーへの変更、ミュート設定要求、読み戻しによる成功の順にログが記録され、音量設定が維持されることを確認する。
4. イヤホンを再接続する。自動ミュートの解除操作が行われず、監視が続くことを確認する。
5. 内蔵スピーカーでミュートを手動解除し、再接続・切断を繰り返す。各切り替えで処理されることを確認する。手動の出力切り替えも確認する。
6. 自動ミュートをOFFにして同じ切り替えを行い、操作されないことを確認する。OFFのまま終了・再起動し、選択が維持されることも確認する。

続いて小さな音量で音声を再生し、切断直後に音声が漏れるかを確認します。再生アプリがイヤホン切断時に自動停止する場合、その試行だけではAutoMuteによる音漏れの抑制を評価できません。ログの読み戻し成功と、実際に音が聞こえなかったことは分けて確認します。

ログイン時起動の確認には実際のログアウト・再ログインが必要です。作業を保存し、利用者が実行できるタイミングで確認してください。
