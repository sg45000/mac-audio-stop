# AutoMuteの設計方針

## 目的と判定条件

再生アプリに依存せず、Bluetoothイヤホンから内蔵スピーカーへの出力変更時にOSのミュート機能をONにする。出力変更理由の判別は行わず、手動で内蔵スピーカーへ切り替えた場合も対象とする。

MVPでは次のすべてを満たす場合だけ操作する。

1. 初期状態取得後の変更である。
2. 変更前はBluetoothまたはBluetooth LEのデフォルト出力だった。
3. 変更後は内蔵スピーカーである。
4. アプリが監視中であり、書き込み直前も同じ内蔵スピーカーがデフォルト出力である。

メニューバーに自動ミュートのON/OFFを表示し、切り替えと終了を提供する。通常のウィンドウやDockアイコンは設けない。ミュート解除と音量変更はアプリの責務に含めない。切断理由の判別、ログイン時起動、通知、外部出力やマイクの制御は対象外とする。

## ON/OFFの意味

初回はONとし、選択はUserDefaultsへ保存して次回起動に引き継ぐ。メニューには設定値ではなく、実際に監視がONかOFFかを表示する。

OFFでは出力監視を解除し、反映確認待ちも中止する。既に要求したミュートの取り消しはしない。ONへ戻すときは現在の出力を新しい初期状態とし、OFF中の変更をさかのぼって操作しない。困ったときに停止でき、ユーザーが戻した音声設定を再び変更しないための方針とする。

監視開始に失敗した場合はOFFを保存して常駐を続け、メニューに失敗を表示する。ユーザーはメニューから再度ONにできる。終了時には現在のON/OFFの選択を変えず、監視とメニューバー項目を終了する。

## デバイス識別と監視

Core Audioの`kAudioHardwarePropertyDefaultOutputDevice`をイベント駆動で監視する。名前の文字列一致やUIDの内容解析は行わない。内蔵スピーカーはBuiltIn Transportと出力ストリームの端子種別を組み合わせて識別する。Core AudioのSpeaker定数とIOAudioのOUTPUT_SPEAKER定数を扱い、端子不明・出力なし・ヘッドホン等との混在は対象から外す。

デバイスIDとUIDを組み合わせて同一出力を判断する。切断後の旧デバイスに問い合わせず、名前・種類を含むスナップショットを保持する。デバイス情報は取得時に更新し、IDの再利用や再生成に備える。

すべてのリスナーと状態更新をmainキュー・MainActorへ集約する。リスナーを登録してから初期出力を取得し、初期取得では操作しない。取得中に出力が変わった場合やAPI失敗時は、判定を中断して前回状態を未確定に戻す。次の正常取得を新しい初期状態とする。見逃しの可能性を許容し、古い情報から推測してミュートすることを避ける。

ミュート要否はスナップショットを受け取る純粋関数で判定し、監視と操作の接続はAutoMuteControllerが担当する。前回状態は操作前に更新するため、ミュートに失敗した場合も同じ出力の重複通知で再試行しない。ユーザーがミュートを解除しても、次の対象遷移までは再操作しない。

## ミュート操作

出力スコープ・Main要素の`kAudioDevicePropertyMute`について、プロパティの存在と書き込み可否を確認する。対応していない場合はログを残し、チャンネル別操作や音量0へのフォールバックは行わない。

既にONなら書き込まない。変更リスナーを先に登録してからUInt32の1を書き込み、通知後の読み戻しで反映を確認する。通知がない場合は1秒後に一度読み戻して終了し、周期ポーリングや自動再試行はしない。設定要求の受理と反映確認を区別して記録する。

別の出力変更が発生したら前の反映確認待ちを中止し、新しい遷移を判定する。反映確認待ちが後続のミュートを妨げないようにし、既に行ったミュート書き込みを取り消す操作は行わない。成功・失敗にかかわらず出力監視を継続する。

Core Audioの操作は非同期になり得る。書き込み直前の出力再確認でも、その後の切り替えとの競合を完全には排除できない。イベント通知後の方式では一瞬の音声漏れも保証できないため、実機で評価する。事前ミュート方式はMVPには含めない。

## 検証とライフサイクル

自動テストでは実機の音声設定を書き換えず、Core Audio操作の境界を代替実装に差し替える。デバイス分類・判定と、監視からミュートまでの一連の動作、OFFと再開、設定保持を検証する。設定のテストは専用の一時ドメインを使い、普段使いの設定を変更しない。Debug・Releaseとも通常起動でメニューバーを表示し、前回のON/OFFを復元する。手動の一度限りの実機検証にはDebug限定の明示的な検証用起動引数を使い、この起動では常駐の自動ミュートを開始しない。

リスナーは登録したブロックとキューを保持して解除する。正常終了時には待機中の確認処理も中止する。強制終了時の後処理・終了ログは保証しない。

Loggerに起動・終了、変更前後の出力、設定要求、確認結果、Core AudioのOSStatusを記録する。UIDは照合に使うだけでログへ出力しない。外部へのデータ送信や独自のログファイル永続化は行わない。
